Security Policy

ATAMO welcomes responsible security disclosures and outlines core principles for protecting the ATAMO system. This page guides security researchers, auditors, and community members on reporting potential vulnerabilities, understanding our defensive measures, and monitoring governance activity.

Scope & Expectations

This security policy applies to ATAMO’s digital assets, deployed smart contracts, administrative governance processes, and the official website. It does not cover third-party integrations or external services outside the ATAMO project.

  • Responsible disclosure: Submit potential vulnerabilities privately before public disclosure.
  • Contact method: Use the official disclosure channel listed in security.txt or encrypted PGP communication using the ATAMO public key.
  • Expected response: We aim to acknowledge all reports within 48 hours and provide updates on remediation progress when possible.
  • What to report: Software vulnerabilities, smart contract exploits, governance issues, and suspicious activity impacting ATAMO.

Responsible disclosure

ATAMO encourages responsible private disclosure of potential vulnerabilities. Public disclosure should be avoided until the issue has been reviewed and, where appropriate, addressed.

Security contact

Security reports should be sent through the official disclosure channel. The contact address is published in the project’s security.txt file.

Encrypted communication is supported using the ATAMO public PGP key.

Disclosure expectations

  • Provide a clear description of the issue.
  • Include reproduction steps where possible.
  • Allow time for review before public discussion.

Security principles

Multi-signature control

Sensitive authority is intended to be managed through a multisignature structure rather than a single administrative wallet.

Timelocked execution

Critical administrative actions must pass through a review period before execution, supporting transparency and external monitoring.

Minimal web attack surface

The official website is static and informational, reducing unnecessary server-side complexity.

Governance activity should be monitored through the public blockchain, the official contracts page, and the verification guidance published by the project.
